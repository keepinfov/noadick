# noadick

Игровой Telegram-бот на aiogram 3: ежедневная игра, дуэли, полноценный
no-limit Hold’em, рейтинг, болезни, вклады и кредиты. Состояние хранится в
SQLite. Управление чатами, игроками и
экономикой доступно из Telegram глобальным администраторам.

## Команды

| Команда | Описание |
|---|---|
| `/dick` | ежедневное изменение размера |
| `/duel [ставка]` | дуэль ответом на сообщение или открытый вызов |
| `/poker` | No-limit Hold’em на сантиметры или учебные фишки |
| `/me` | профиль и статистика игрока |
| `/stats` | подробная статистика, PNG-графики и CSV в личке |
| `/top` | график и топ-10 в чате с кнопкой подробностей в ЛС |
| `/bank` | вклады и кредиты |
| `/corp` | состояние Корпорации |
| `/settings` | настройки текущего чата для его администраторов |
| `/help` | список команд |
| `/ping` | проверка отклика |
| `/admin` | глобальная админ-панель для ID из `ADMIN_IDS` |

В админ-панели можно управлять чатами и игроками, банами, болезнями,
рассылками и глобальными параметрами. Раздел «Экономика» показывает ликвидные
средства, вклады, кредиты, покрытие обязательств Корпорацией и динамику за 7/30
дней. Изменения администраторов записываются в `audit_log`.

Покер ведёт одно редактируемое табло в группе или теме, а карты и действия
показывает каждому игроку в личке. Денежный бай-ин резервируется из размера
исходного чата; приватные учебные столы не влияют на экономику. Для карточек
приглашения через `@bot` необходимо включить inline mode командой `/setinline`
у BotFather. Основная игра от inline mode не зависит.

Отрицательный результат `/dick` теперь не отрезает размер мгновенно: он
становится срочной частью долга, видимой в `/bank`, и после срока взыскивается
как кредит. Срок настраивается в глобальной банковской панели.

Игроков с суммарными активами меньше 20 см защищает ПИСЯГО: отрицательный
`/dick` покрывается на 100/75/50/25% в зависимости от размера, вклада и
денежного покерного стека. За один семидневный период страховка прикрывает не
больше 20 см; порог, запас и период меняются в глобальной админ-панели.

У каждого группового чата своя Корпорация. Первые 3 см положительного `/dick`
покрывает явно учитываемая эмиссия, остальное — только свободная локальная
касса; 25% обязательств по вкладам зарезервировано. Добровольное СЕКАСКО за 5%
защищает до 40 см тела вклада. Если касса не выдерживает снятие, включается
семидневная санация, после которой незастрахованные вклады списываются.

Кредитный рейтинг нельзя набить мгновенными микрозаймами: зачёт получает лишь
достаточно крупный кредит возрастом от трёх дней, не чаще раза в 14 дней.

`/stats` открывает приватную панель с периодами «сегодня / 7 / 30 дней / всё
время» и разделами роста, дуэлей, банка, покера, PISYAGO и Корпорации. Игрок
видит подробности только о себе, администратор — о своём чате, глобальный
администратор — обо всей системе. Каждый раздел можно выгрузить в CSV. В
`/settings` администратор может включить недельный дайджест и выбрать день и
час публикации по часовому поясу чата. Старые доступные события учитываются,
а показатели, которым раньше не хватало деталей, явно помечаются датой начала
точного учёта.

Команда `/stats chat` доступна всем участникам группового чата как публичная
гонка текущей десятки лидеров по чистому состоянию: линии соединяют временные
точки и показывают обгоны. В состояние входят наличка, вклад с начислениями и
активный покерный стек за вычетом долгов. Финансовые и корпоративные разделы
по-прежнему доступны только администраторам.

В `/me` длина и чистое состояние показаны отдельно: у каждого показателя своё
место, поэтому вклад или долг больше не маскируются под физическую длину.

## Production

Создай `.env` по образцу `.env.example`, укажи `BOT_TOKEN` и при необходимости
`ADMIN_IDS`, затем запусти:

```bash
chmod 600 .env
docker compose up --build -d
```

Это единственная команда развёртывания. Compose сам подготавливает права bind
mount, после чего бот работает без root, с read-only корневой ФС, сброшенными
capabilities и healthcheck. База находится в `./data/bot.db`, резервные копии —
в `./data/backups`.

Полезные команды:

```bash
docker compose ps
docker compose logs -f bot
docker compose down
```

## Разработка на NixOS

Версии инструментов закреплены в `flake.lock`, Python-зависимости — в
`uv.lock`:

```bash
nix develop
uv sync --frozen
uv run pytest
uv run ruff check .
uv run ruff format --check .
pyright
```

Запуск бота локально:

```bash
uv run python bot.py
```

Отдельный детерминированный отчёт роста для оценки баланса без изменения
игровых коэффициентов:

```bash
uv run python -m scripts.economy_report --trials 5000
```

В группах команда `/season` показывает предварительные итоги текущей
календарной недели и архив завершённых сезонов. Сезоны ведут только статистику:
они не выдают призы и не меняют баланс. Администратор чата может включить
автоматическую недельную публикацию и выбрать её локальные день и час через
`/settings`.

## Конфигурация

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен от BotFather, обязателен | — |
| `ADMIN_IDS` | Telegram ID глобальных администраторов через запятую | пусто |
| `DB_PATH` | путь к SQLite | `./data/bot.db` |
| `TZ` | часовой пояс ежедневного сброса | `Europe/Moscow` |
| `PROXY` | `http(s)`, `socks4` или `socks5` прокси | пусто |
| `BACKUP_DIR` | каталог резервных копий | `./data/backups` |
| `BACKUP_INTERVAL_HOURS` | период копирования; `0` отключает | `24` |
| `BACKUP_RETENTION` | число сохраняемых копий | `7` |
| `LOG_FORMAT` | формат логов: `json` или `text` | `json` |

Параметры проверяются до подключения к Telegram. Токен и учётные данные прокси
в логи не выводятся; ID пользователей и чатов в контексте логов хешируются.

## База и миграции

Alembic автоматически применяет миграции перед запуском бота. Перед этим для
существующей непустой БД создаётся проверенная SQLite-копия. Ручной запуск:

```bash
uv run alembic upgrade head
```

Старые JSON-файлы из `storage/<md5(chat_id)>.json` импортируются в staging:

```bash
uv run python -m scripts.migrate_json ./storage
```

После первого сообщения из чата бот связывает MD5 с реальным `chat_id`. До
этого чат не виден в админке, поскольку исходный MD5 необратим.

## Архитектура

```text
bot.py                  точка входа, middleware, фоновые задачи
config.py               проверяемая конфигурация окружения
db/                     async SQLAlchemy engine, модели, запуск Alembic
migrations/             версионируемые миграции схемы и данных
repositories/           слой доступа к данным
services/               игровая, банковская и административная логика
handlers/               Telegram-команды и callback-обработчики
observability.py        JSON-логи с анонимизированным контекстом
scripts/                импорт, healthcheck и симулятор экономики
tests/                  unit- и интеграционные тесты SQLite
```

SQLite работает с включёнными foreign keys, WAL и ожиданием занятой записи.
Polling рассчитан на один экземпляр бота. Горизонтальный запуск
нескольких реплик потребует внешней БД и координации polling/webhook.
